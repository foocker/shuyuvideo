# 视觉基线审查与验证

2026-10-30。使用 aesthetic-audit 的视觉取证与可执行参数方法，按本次视频风格任务调整审查重点。

## 1. 结论

现有案例已经形成暖白、灰绿、柔和体积的共同视觉身份；需要统一的是跨作品的颜色职责和新片默认值。当前通过 `tokens.json` 固定来源和用途，并以真实原片静帧及新的 Manim 静态样张对照。

## 2. P0 / P1 / P2

### P0

本轮未识别出要求推翻现有风格的视觉问题。此结论仅限选取的静帧和源码，不表示所有历史作品完成了全片视觉验收。

### P1 · 相近背景分散在多个工程

- 现象：人体 `#F4F2EC`、字形 `#F5F3EC`、莫比乌斯 `#F7F4E8`、解环 `#F7F7F3`，角色展示又有独立底色。
- 影响：跨引擎拼接时可能出现无意的底色跳变。
- 原因假设：各作品独立创作，没有共享参数源。
- 修改建议与落实：新片默认 `background=#F4F2EC`，其他原值记录为来源变体；历史作品不批量改色。

### P1 · 填充色与文字色需要分工

- 现象：浅青绿、赭金在暖白底上对比度分别约 1.93:1、1.95:1。
- 影响：直接用于小字、细公式或关键边界时难以辨认。
- 原因假设：物体的大面材质色被误当成所有元素通用的强调色。
- 修改建议与落实：正文、注释、文字强调分别用 ink、muted、emphasis；浅色用于大面，必要时补深色轮廓。对应职责与对比度报告已生成。

### P1 · 全局换色会改变数学编码

- 现象：人体七色追踪、字形五色身份、映射陶红各有不同职责。
- 影响：一刀切改成青绿会丢失对象对应；把陶红一律当错误也会改变意义。
- 原因假设：只按 RGB 而非语义对象设计主题映射。
- 修改建议与落实：将两个既有语义色组独立保存；外部片段按对象/变量/状态建立映射后适配源码。

### P2 · 材质、排版还没有统一可移植参数

- 现象：不同三维项目使用不同光强、曝光和粗糙度，中文字体使用工程子集。
- 影响：仅复制色值不能确保最终画面一致；旧字形子集也不覆盖新文案。
- 原因假设：参数依赖场景尺度与运行环境，尚未经过跨渲染器验证。
- 修改建议与落实：记录观察范围和新片起点，明确来源值与建议值；字体需在作品中固定实际文件。Manim 仅提供显式颜色与文字辅助函数，不冒充 Three.js 材质适配器。

## 3. 已落地的参数

- 颜色：16 个角色值，逐个关联本地源码；`build-style.py` 验证色值确实存在于对应文件。
- 排版：1080p 标题 68 px、说明 34 px、注释 28 px 为来源起点；公式 52 px、间距序列、辅助线宽等新建议明确标注。
- 材质：主实体粗糙度观察范围 0.64–0.82、金属度 0–0.03；新物体建议 0.76 / 0。
- 输出：JSON 为编辑源，CSS 与浏览器 JS 为生成文件；Manim 从同一个 JSON 读取。
- 语义：五对象色与人体七色独立于基础品牌色。

## 4. 可立即采用的改进

1. 新片各渲染部分读取相同的背景与文字角色值，合成时检查接缝。
2. 将浅青绿与金色保留给物体，正文改用 ink，重要注释改用 muted。
3. 给每个语义对象保存稳定 ID 与颜色映射，形变和换位时继续使用。
4. 在正式渲染前先做包含标题、公式、曲线和实体的静态样张，检查小字与边界。
5. 每个外部片段记录来源版本、改动和实际验证，样张成功不等于整条外部流水线成功。
