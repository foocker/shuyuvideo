# B 站发布资料与手动填写

共用成片确认：`films/<作品>/publish/video.json`。平台字段：同目录 `bilibili.json`。从 `publish init` 生成后编辑；生成物位于 `output/<项目>/publish/bilibili/`。

## 字段

| 字段 | 含义与填写方式 |
| --- | --- |
| `account.homepage/name` | 目标账号主页及显示名；填网页前另核对实际登录账号 |
| `title` | 完整视频标题，最多 80 字符 |
| `copyright/source` | `original` 自制或 `repost` 转载；转载须保留来源，与创作声明分开 |
| `creation_declaration.label/note` | `label` 记录网页实际选项；未读取选项时用 null。`note` 写实际使用的文稿、配音、图像等制作方式，不能凭“自制”跳过 AI 声明 |
| `category.path/verified` | 分区名称层级数组。建议可先填，实际网页核对后才将 `verified` 改为 true；不硬编码未核实的分区 ID |
| `tags` | 1–10 个独立标签，数组中不要加 # 或逗号；不自动采用推荐标签 |
| `description` | 最多 2000 字符；问题、内容与必要限定，按需包含章节时间 |
| `topics` | 平台活动话题，与普通标签分开；默认空数组，不参加无关活动 |
| `schedule` | null 为不启用定时；否则如 `2026-11-08T18:00:00+08:00`，每次检查重新计算距当前 5 分钟至 15 天 |
| `collection` | null 为不加入；否则用已有合集的准确名称，并核对账号权限 |
| `commercial.enabled/details` | 是否包含商业推广及其具体信息 |
| `more_settings` | 按真实页面记录 `{label, action, value}`；`review` 待查看，`keep` 已查看后保留，`set` 明确填写目标值 |

长度与时间限制依据用户 2026-11-07 提供的投稿表单。字符检查保守使用 UTF-16 单元；平台可能调整规则，最终以页面计数和提示为准。没有实测的下拉选项不编造成固定枚举。

`more_settings` 初始列出“声明与权益、视频元素、互动管理”三个待查看分组；展开后应细化为真实选项。只在已查看且决定保留时使用 `keep`，不是默认跳过。未知或不可用的合集、声明与选项要向用户说明，不能静默省略。

## 手动填写

1. 制作端运行 `publish build` 和 `publish check`，交付本地 `index.html` 链接。页面可逐项复制，纯文本文件供备用；用户无需执行上传命令。
2. 用户点击页面的“打开 B 站投稿页”，确认自己的登录账号，按页面给出的本地路径选择 MP4 与 JPG。
3. 复制标题、简介和标签到投稿表单。标签逐个确认，活动话题另行选择；查看封面裁切和视频上传状态。
4. 创作声明、分区和更多设置由用户按实际网页选项填写。页面中的“待核对”是填写提示，不妨碍本地资料交付；需要保存这些选择时再更新平台 JSON 并重新生成页面。
5. 用户核对后自行保存草稿或发布。若选择定时，使用 Asia/Shanghai 并遵循平台当前允许的时间窗口。

这套流程不依赖浏览器控制工具、命令行登录或 Cookie 配置。`check --ready` 是用户已核对选项后的可选检查；只有本地检查成功不能推断平台草稿已保存或发布成功。
