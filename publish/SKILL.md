# 数语平台发布

成片确认与平台投稿独立于视频制作。共用一份已确认的视频和封面，每个平台分别维护标题、文案与选项。2026-11-07 用户最终选择：“就手动上传吧。能做到当前这样的填写页面就行了。”默认交付本地资料页，用户自行上传、填写和发布。

## 从已有交付开始

- 读取作品简报、文稿、`delivery.json` 和本次要求，沿用已确认的成片与标题。不要为发布重新配音、渲染或改封面。
- `films/<作品>/publish/video.json` 管理跨平台共用的成片确认，绑定视频与封面的 SHA256。用户已在会话认可当前成片时直接记录依据，不再问一次；未认可或文件改变时先给出可审阅文件。
- 平台稿放同目录 `<平台>.json`。当前 `bilibili` 已实现；`xiaohongshu` 与 `tencent` 保留为后续适配目标，不能宣称已支持。
- 账号主页、显示名可保存在忽略的 `publish/profiles.local.json`；主页仅表达目标账号，不证明浏览器已登录该账号。Cookie 与登录凭据不写入发布资料。

```powershell
.\shuyu.ps1 publish init <项目> --platform bilibili
# 编辑 films/<作品>/publish/bilibili.json
.\shuyu.ps1 publish approve <项目> --note "用户确认的原话及上下文"
.\shuyu.ps1 publish build <项目> --platform bilibili
.\shuyu.ps1 publish check <项目> --platform bilibili
```

`init` 不覆盖旧稿；`approve` 只记录真实已有确认。`build` 输出本地填写页、文本文件、封面副本与发布包，不复制大视频。`check` 拒绝旧版本、缺文件、超长字段和过期定时；`--ready` 可在用户已核对选项后使用，不是交付本地页面的前提。`assist` 保留为生成同一份本地资料的兼容入口。

## 平台适配

B 站使用 [字段与手动填写流程](references/bilibili.md)。根据本片解释主线写简介和标签，不照抄页面的无关推荐标签，不把全文口播塞进简介。封面继续使用本片短钩子，标题可以更完整。

交付 `output/<项目>/publish/bilibili/index.html`：保留封面预览、视频和封面路径、各字段复制按钮、投稿页链接及待用户核对项。创作声明、分区和更多设置没有确认时保持待核对，用户在平台填写即可；不要求用户先配置账号凭据，也不默认启动浏览器自动化。

用户提供发布结果后，可记录平台稿件 ID、链接和状态，并注明信息来源；“已提交审核”不等于公开可见。本地资料生成不能记成平台草稿或投稿成功。

## 外部上传后端

已审查 [social-auto-upload](references/social-auto-upload.md)，评估仅留作参考。当前用户选择手动上传，不安装、登录或调用自动上传后端。以后只有用户明确恢复自动化需求时再评估接入。`publish backend` 展示所审查版本与当前未启用状态。

新视频文件、平台配置、账号状态和发布产物只留本地。Git 仅维护公共模块与必要的通用案例；README 使用精选 GIF，不每片追加。
