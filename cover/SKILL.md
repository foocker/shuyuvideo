# 数语封面

每部影片交付一个 MP4 和一张独立 JPG。封面在定标题、写开场钩子时一起考虑，不等成片后随机截一帧。

## 设计

默认只保留**一个清楚的视觉主体 + 一句短钩子**。画面留白，大字在手机缩略图上仍读得清。钩子与片内解释有真实联系；完整视频标题保存在元数据里，不必全部挤上封面。不要默认添加副标题、标签、公式、角标和装饰。

例如“数学中的光滑”可以用一小块局部肌肤配“你好光滑”。这是本片的具体方向；其他片按内容选主体和钩子，不套肌肤模板。

把构图、文字、来源与检查记录写进作品 `COVER.md`。已确认的方向直接沿用。用户指定摄影时寻找或生成真实图像；生图不可用时说明并采用用户允许的替代方法，不以假结果交差。

## 素材与构建

- 底图、原创插画或已设计完成的整张封面保存在作品 `assets/cover/`，不得只留工具缓存或远程链接。
- 使用允许本片用途且无需画面署名的素材，来源和许可证留在内部记录。生图按实际可用工具的技能执行；TapCanvas `/public/*` 统一通过 `tapcanvas-api`。重建封面不重复调用模型。
- 作品 `cover.json` 保存排版与本地图像路径，格式见 [文件契约](references/files.md)。中文标题本地排版；已有完整封面可直接用 `ready` 模式。
- `shuyu cover build <项目>` 离线生成 JPG 和 360px 宽缩略图；`shuyu cover check <项目>` 检查输入与成品是否同步。
- 实际查看生成的原图和手机图，核对主体裁切、字形、可读性和钩子。记录在 `COVER.md` 或 `REVIEW.md`；机器通过不表示已看图。

## 成对交付

`shuyu render <影片>` 先预检封面，成片测量通过后生成 JPG 和 `delivery.json`。品牌片头与技术示例不强制附封面。

已有 MP4 使用 `shuyu deliver <项目>`，补封面、测量视频并绑定双文件摘要，不重渲染。`shuyu deliver <项目> --check` 验证本次交付没有缺失、替换或过期。

最终给用户链接：`output/<项目>/renders/<片名>.mp4` 与同目录 `<片名>-cover.jpg`。中间底图与缩略图是制作材料，不算额外交付。历史作品不批量回填；只有本轮制作或修改的片子进入这套交付。
