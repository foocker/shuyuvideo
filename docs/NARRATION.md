# 口播稿规范

讲解模式由口播稿决定全片的节奏。写稿与改稿先读 [口播写作模块](../writing/SKILL.md)：先确定理解过程与画面承担的解释，写好自然段，再生成配音，最后按配音的实际时间实现画面。

`mode: story-animation`（无讲解模式）先按 [剧情动画](../writing/references/story-animation.md) 设计故事与动作，再安排画外配音；不套用下文口播先行的结构。配音文件、读音核对和真实词时间共用；字幕可选，无配音段可以只用动作和声音推进。音效锚定动作接触，字幕锚定真实语音，片尾动作也须计入声音总长。

## 写之前回答三个问题

1. 观众开始时知道什么？（例：会加法，不知道求和公式）
2. 看完后多理解了哪一件事？只写一件。（例：$1+2+\cdots+n$ 为什么等于 $\frac{n(n+1)}{2}$）
3. 哪个画面承担这次理解？（例：两道台阶拼成长方形）

## 结构

下表是 60 秒操作讲解的一种参考。长片、历史叙述和概念推理按问题组织，不必凑齐五段或固定比例。文章章节不要直接压缩成连续的概念介绍。

| 段 | 作用 | 时长参考（60 秒片） |
| --- | --- | --- |
| 问题 | 一个具体问题，观众能自己试一下 | 5–8 秒 |
| 尝试 | 直接算的困难，或一个小例子 | 8–12 秒 |
| 关键操作 | 一个画面动作，带出答案 | 20–30 秒 |
| 结论 | 一句话说出结论和公式 | 6–10 秒 |
| 边界 | 结论在什么条件下成立；或留一个问题 | 0–8 秒 |

## 句子

- **先写连贯段落。** 句长随语义变化，按正常呼吸和完整意思拆配音单元；不设 25 字硬上限。字幕长度单独处理。
- **口语。** 写"把它倒过来"，不写"对其进行翻转操作"。
- **指代具体。** 画面出现台阶时说"台阶"；旁白也可解释原因或补充必要背景，不要求每句话都是动作说明。
- **术语先出现物体，再给名字。** 先看到长方形，再说"长方形的面积"。
- **不念画面上的字。** 屏幕显示公式时，口播解释公式的意思，不逐字读出。
- **公式的读法写成汉字。** 稿中写"n 乘 n 加一，除以二"，配音才读得准。屏幕上的公式另外用 TeX 写。
- **给停顿。** 关键操作后留出观察时间；0.6–1.2 秒可作为简单动作的起点，按内容和试听调整。

## 信息密度、语速与留白

每部视频都检查内容密度与讲述速度是否相配。用户在 2026-11-07 明确提出：信息量不大的段落空白偏多，应在少数地方加快，并将这一策略用于后续制作，随反馈逐步优化。

- **先判断理解负担。** 新定义、条件、推导和需要追踪的图形变化维持清楚的基准速度；熟悉内容的回顾、过渡和重复说明可稍快。字数少不等于信息少，短公式或关键否定也可能需要停留。
- **少量局部变化。** 对 3–5 分钟讲解片，通常选择 1–3 个连续片段，初次可比基准快约 8%–12%；这只是起点，不是每片必须完成的配额，也不据此裁短长片。按完整意思切换，避免句中突然变速。
- **先处理多余静音。** 实际句间留白 = 前一句音频尾部静音 + `pause`/`gap` + 后一句音频头部静音。先缩短多余间隔，再调整说话速度；不能只看 JSON 里的停顿。最后一句还要一起检查其 `pause`、全片 `tail` 与音频尾部，避免重复叠加。
- **停顿有解释任务。** 观察、比较、结论落定、提问可以留白；画面和声音都没有新进展的停留应收紧，不靠增加装饰动画填空。复杂画面所需的观察时间优先于加速目标。
- **写稿时标记，配音后落实。** 在 `DIRECTION.md` 记录低／中／高理解负担、选段原因、语速和停顿意图；行级 `rate`、`pause` 写在登记稿件。取得真实音频后，重算逐词锚点、字幕、镜头、Omega 和音效，必要时重渲染受影响的数学短片。
- **记录验证边界。** 成片检查加速段前后衔接、字幕读取时间和句间静音，保存改前／改后时间与实际试听情况。自动计时、响度和抽帧不等于听感通过；用户后续反馈继续修正范围与幅度。

例如全局 `rate: "-3%"` 时，回顾段设置 `rate: "+6%"` 约比基准快 9.3%；`rate: "+8%"` 约快 11.3%。百分比是相对语音引擎默认速度的绝对设置，不能当作在全局速度上继续叠加；实际时长以生成音频为准。

## 文字与画面分工

让内容本身简单：底部字幕承接口播的完整句子，主画面展示对象、变化和关系。观众听一句话时，不应还要读画面中同一句放大的文案。

- 完整的反问、生活化解释和过渡句通常只放字幕；例如“总不能伸手摸一摸吧？”无需在曲线旁再写一遍。
- 章节标题用短主题词，默认不再加解释性副标题。删除文字后让图形和留白承担构图，不用新的文案填空。
- 保留有独立作用的定义、公式、对象名、关键条件与对照标签；“输入/输出”“真实增量/近似”等帮助认出画面的标签不机械删除。
- 图形能呈现的变化直接呈现，口播解释原因。需要回顾时保留少量概念与符号，避免整句复述；片尾问题可用对象与问号承接字幕。
- 定稿时逐段同时看主画面和字幕，按理解作用删减，不能只做字面重复检测。

## 正文与配音文件

`SCRIPT.md` 给人编辑：正文按段落写好后，采用 [文稿文件契约](../writing/references/files.md) 标出行 ID 和配音配置。对应画面、停顿意图与屏幕 TeX 公式放 `DIRECTION.md` 或简报，正文不夹制作备注。旧构建会生成 `SCRIPT.md` 时，导入为 `SCRIPT.writing.md` 并以它为编辑入口。

```powershell
.\shuyu.ps1 writing import films/<作品> --script SCRIPT.writing.md
.\shuyu.ps1 writing export films/<作品> --dry-run
.\shuyu.ps1 writing export films/<作品>
.\shuyu.ps1 writing check films/<作品>
```

新稿可参考 [可执行口播样例](../examples/writing/SCRIPT.md) 的格式后直接导出。导入不覆盖已有稿件，导出不调用模型改写正文。`.writing.json` 记录编辑入口与最后导出的配音摘要，随作品保存；仅登记的作品启用同步检查。其他旧作品保留原有输入方式。

`narration.json` 给程序读，`sound/voice.py` 读取它生成配音：

```json
{
  "voice": "zh-CN-YunxiNeural",
  "rate": "-3%",
  "gap": 0.35,
  "lines": [
    {"id": "q1", "text": "从一加到一百，等于多少？", "pause": 0.8},
    {"id": "k1", "text": "再拿一道一模一样的台阶，倒过来，拼上去。", "pause": 1.0}
  ]
}
```

- `text`：只写要读出来的字。不放 TeX、括号备注或斜杠。
- `pause`：这句之后到下一句的间隔秒数，替代默认 `gap`，两者不相加。
- 行级 `rate`：覆盖全局 `rate`，格式如 `"+8%"`，未设置的句子继续使用全局速度。它控制真实配音生成；改速会使对应音频缓存失效，需要重建后续时间轴。
- 配音生成后得到 `voice-timings.json`，里面有每句的开始、结束时间和逐词时间。画面的关键动作对齐到词的时间，例如"倒过来"这个词开始时，台阶开始翻转。

## 检查

### 多音字与术语读音

“数”表示逐一计数时读shǔ（三声），例如“数学到底在数什么”“十七，数的是对称规则”；“数学、整数、数目”等名词中的“数”读shù（四声）。2026-11-09用户指出本片约03:23误读，已采用此纠正。当前引擎可用完整短语提示`{"在数":"在鼠","数的是":"鼠的是"}`，不能全局替换单字“数”，以免误改同句“数学”。

2026-11-09，用户指出《平面对称群》约2分26秒将“重”读成zhòng。“二重、三重、四重、五重、六重旋转／对称”的“重”应读 **chóng**，与“重复、重合”同音；“重要、重量”仍读zhòng，不能全局替换单字。

- 写稿后列出数学术语、多音字、人名和外文读法；配音后复核真实音频中的这些位置。文字正确、ASR转写正确和响度合格都不等于读音正确。
- 当前Edge TTS不接受任意SSML音素标签。确认误读时，可在登记稿件的`shuyu-voice`或行标记中增加`pronunciations`，用同音、同声调、等字数的汉字明确发音，例如`{"五重":"五崇"}`。该字段只用于TTS，正文、字幕及画面仍是“五重”。不能以改变术语含义的改写代替纠音。
- 字典按完整词匹配，优先较长词；行级相同键覆盖全局。替换内容不递归处理。发音输入纳入缓存指纹，已纠正的声音不能被旧缓存覆盖；逐词时间映射回原文后用于字幕和动作锚点。
- 改读音后重新生成受影响句、更新真实时钟、镜头、数学片段、字幕和混音；保留纠音词表及实际验证方式。未试听时如实记录，不宣称全部读音已听审通过。

字幕按真实词时间拆分长句，不能只按字符比例估算切点。修改口播后重算镜头、Omega、字幕和音效锚点；外部 SRT 根据是否附加片头统一偏移。字号和遮挡检查见 [交付核对](VALIDATION.md#交付核对)。

- 逐段检查引入动机、推理衔接与指代。实际朗读或试听后修改读不顺的句子；仅看文字时如实记录。
- 数学表述与 Astra 审核记录或数学依据一致；近似、条件、例外都说出来。
- 检查没有独立作用的预告、重复和评价；不按词表机械删句。自动文稿检查不评价文风或数学正确性。
