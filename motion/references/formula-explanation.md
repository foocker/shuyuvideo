# 动画与公式一起讲解

公式排版、公式动作、数学求解是三件事。TeX 决定符号怎样排，GSAP / Manim 等决定怎样呈现，数学模型决定哪些变化成立。不要因为画面出现积分、字母移动或公式变形，就指定整个镜头必须用 Manim。

以下是数语的实现建议，例子均为原创，可独立使用。

## 先决定公式承担哪一步解释

把每次变化写成一种明确的数学操作，再选动效：

| 操作 | 画面做什么 | 要保留什么 |
| --- | --- | --- |
| 介绍符号 | 先指认图中对象，再显示符号和短注释 | 符号、所指对象、单位与正方向 |
| 逐项揭示 | 预排完整公式，按语义组显现 | 已出现部分的位置、整式基线 |
| 添加项（改模型） | 保留旧式，突出新增项，再比较行为 | 明示模型已改变；不是等式推导 |
| 加约束 | 将条件写在目标之外，展示违反条件的候选被排除 | 可行性与代价大小是不同判据 |
| 代入 / 等价整理 | 相同对象移动，新增表示显现，给出中间依据 | 等价条件、符号身份、项的来源 |
| 为一组项命名 | 同色标出贡献项，归并为一个新符号，保留展开定义 | 多对一的语义映射，不能仅按字形匹配 |
| 图与公式对应 | 同一量的箭头、曲线、读数和公式同时强调 | 同一数据源、同一时间与单位 |
| 简化模型 | 明示“只看某方向 / 忽略某因素”，再换状态与公式 | 简化前提及与原模型的区别 |

例如从 `平均 = (a + b) / 2` 变成 `平均 = w·a + (1 − w)·b`，必须说“改成按权重平均”，这不是等式变形。从 `2x + 3y + 4x` 整理成 `6x + 3y`，则需要说明按 x 收集系数。以上为文字释义，正式屏幕公式仍用 TeX。

## 按动作选择实现

| 需要 | 首选实现 | 边界 |
| --- | --- | --- |
| 公式入场、着色、括注、整体缩放、与图形联动 | HyperFrames + KaTeX + GSAP / SVG | KaTeX 是排版器，动作由时间轴负责 |
| 少量项的位移、追加、替换、分组归并 | 同上；显式保存语义分组和前后布局 | 不依赖 KaTeX 内部生成节点的偶然顺序 |
| 大量连续代数推导、复杂项匹配、精确几何共演 | Manim `MathTex` + `TransformMatchingTex` 等 | 匹配也需核对语义，重复同名字母不保证是同一对象 |
| 真正沿轮廓书写、复杂字形轮廓变形 | 可控 SVG 路径 / Manim | 普通遮罩擦入不等于笔顺书写；KaTeX HTML 不是通用字形路径 API |
| 三维物体带公式说明 | Three.js 主体 + HyperFrames 的公式与标注层 | 需要随物体移动的标注使用投影锚点，不手调关键帧猜位置 |

现有 `style/adapters/tex.js` 负责初始排版，不具备自动语义匹配、公式归并或共享物理状态绑定。GSAP、SVG、KaTeX 已在工作区可用，但这不代表下述候选封装已经实现。先在具体作品验证，再提取公共运行时。

## 公式动作的制作细节

**先排终态，再揭示。** 一整步公式先完整排版，按项控制可见性；只新增透明度时不要用 `display:none` 让后续符号反复重排。需要从短式变成长式时，显式设计前后位置，以等号或主符号为锚点。用 TeX 组处理积分上下限、分式和括号，不逐字拼接成排版不完整的片段。

**语义组先于字形。** 对 `平均`、权重 `w`、数值 `a`、`b`、乘积项 `w·a` 建立稳定 ID。同一字母可能有不同角色；同一量在图中又可能完全不像那个字母。一对多、多对一须由分镜写出映射，不能交给字符串匹配猜测。静态排版可使用受控的 KaTeX 分组扩展，需适配现有严格选项；不要为任意输入全局打开 `trust:true`。另一种方式是离线生成带稳定组 ID 的 TeX/SVG 资产。

**移动与淡变通常足够。** 旧项平移到目标区域并淡出，新命名项淡入，就可以表达“这些项合起来记作 S”。若讲的是代数步骤，先给出可读的收集系数步骤；不能以几百毫秒的交叠代替推导。无语义对应时用明确切换，不强行做形状变形。

**让注意力有顺序。** 先指出图中量，再强调公式项，接着让结果变化，最后停留读取。公式可移到角落保留作参照，当前解释的图占主位。颜色按 [数语风格](../../style/README.md) 的语义职责分配。不要让公式、图形、角色、相机同时做独立的大动作。

**变化完成后再读结果。** 分镜分别写出语义提示点、动作开始、数学状态到达、读取结束；时间由实际口播和复杂度决定，不把统一的 0.5 秒或 1.5 秒当成规律。数学状态的跳变应保留跳变，例如计数从 7 变成 8，不能为了平滑画出 7.5 这样不存在的中间值。

## 让物体、曲线、公式共用状态

建议作品保存以下数据职责，不先扩建统一引擎：

```text
模型 / 求解器 → 带单位和条件的状态序列
                    ├─ 三维姿态 / 二维对象
                    ├─ 曲线、游标、数值与累计量
                    └─ 公式变量、语义高亮与注释

口播时间轴 → 当前电影时间 → 映射到模型时间
           → 当前解释步骤 → 可见性、布局、强调
```

仿真时间和电影时间要分开：慢放、重复比较、冻结讲解可以改变两者映射，但物体姿态、HUD、曲线游标、读数必须使用同一个模型时间。动画缓动只作用于呈现；不得对位置、速度等物理量各自缓动，制造不满足运动方程的中间状态。

一条作品内的分镜记录可以包含：`operation`、`fromEquation`、`toEquation`、`semanticGroups`、`preserved`、`changedAssumptions`、`linkedViews`、`cue`、`settledAt`、`readUntil`。这是候选记录格式，当前没有同名公共 API 或验证器。

三维标注可以让渲染端逐帧导出物体屏幕锚点，再让合成端画箭头和公式。锚点记录需包括帧号/时间、原始画布尺寸和可见性；视频裁切、缩放和位移也要作用到锚点。镜头切换、遮挡、物体离开画面时主动处理，不能只保存 x/y。

## 最小原创验证段

下一次遇到适合的选题，可用“带权平均”验证 20–30 秒的一小段：先显示两个数值来源；用标记建立两个数值与公式项的对应；固定原数值，只改变权重；图中贡献和平均结果一起变化；最后整理成加权和。明确权重非负且和为 1，乘积与和由同一模型计算。时长仅为试作预算。

每次只检验三件事：公式项能否追踪；图与公式是否使用相同数据；新观看者在正常速度下能否说出“变了什么、为什么结果变了”。当前尚未制作该试作，也没有观众理解效果证据。

## 数学与画面共同验收

1. 区分介绍、改模型、加约束、代入、等价整理；不要用相同动画暗示它们全部等价。
2. 核对坐标正方向、单位、边界条件；画箭头表示带符号的量时，箭头方向要与方程取的正方向一致。
3. 面积图必须画实际被积函数。画的是 f 而讲的是 f² 的积分时，要换纵轴或标明示意。
4. 命题成立的条件（定义域、非负、取整数、近似适用范围）写进画面或口播；边界情况和反例不画成一般规律。
5. 对于“最大”“更快”等结论，区分示意曲线、数值结果、必要条件与已证明的结论。示意图不标精确读数，也不把简化模型的结果说成真实系统的精确解释。
6. 检查正序、倒序、任意时间定位时的公式终态与图形读数；检查完整公式的基线、项间距、上下标、局部着色和结果停留。现有 motion 探针只覆盖其数值/截图能力，不自动证明上述语义正确。
